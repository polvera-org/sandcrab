# Sandcrab Phase 1 MVP — Execution Plan

Ship a working V1 on the VPS: `crabd` with native Rust tools over length-prefixed JSON-RPC 2.0, persistent
workspaces, a hardened DockerDev backend (no `docker exec`), SDK + CLI, and a pi-style `crabagent` harness so we
can watch an LLM do real dev work (landing pages) inside sandboxes.

## Flow

Once `protocol` lands, three tracks run in parallel: `crabd` tools (split into exec / fs / search modules),
`core`, and `templates`. They converge on the Docker backend. After the SDK, the e2e tests and the `crabagent`
harness run in parallel.

## Decisions (approved 2026-11-23)

1. **Tool catalog**: Tier 1 complete; Tier 2 `process_start/poll/stdin/kill/list` + `upload/download` (base64, single file);
   `SandboxConfig.ports` published to 127.0.0.1 for previews. Tier 3 browser tools deferred.
2. **Wire framing**: u32 big-endian length-prefixed JSON-RPC 2.0 (`method` = tool name). One protocol for UDS / TCP / vsock. No gRPC.
3. **License**: Apache-2.0 for all OSS crates; revisit control-plane licensing in Phase 3.
4. **MicroVM priority**: Firecracker is pulled into V1 and benchmarked against DockerDev on kvm-homelab. Cloud Hypervisor and libkrun follow in Phase 2.
5. **Security hooks**: typed `network { policy, allow_domains }` + reserved `secrets` in `SandboxConfig`; backends
   that can't enforce them return an explicit error at spawn time (never silently ignore them).
6. **Harness**: in-repo Rust `crabagent` on the Anthropic Messages API (default `claude-sonnet-5-5`, configurable),
   `ANTHROPIC_API_KEY` in the VPS `.env`. A pi-coding-agent adapter comes later.

## Firecracker + benchmark scope

- **KVM host**: Firecracker needs `/dev/kvm`, and the VPS doesn't have it. Firecracker and both benchmarks run on **kvm-homelab** (Proxmox, reached over the tailnet), so the comparison is fair. A spike is checking access now.
- **Workspace model**: Firecracker has no `virtio-fs`, so workspaces have to become ext4 block devices. `fc-design` (Turing) decides how host-side mutation between turns keeps working. That cost is measured.
- **Honest expectation**: Firecracker should win on isolation and, later, on snapshot restore (not in V1). On a cold boot, Docker may match or beat it on spawn latency and per-sandbox memory, since it has no guest kernel.
  The report states what the numbers say, and the default recommendation weighs isolation, not just speed.
- **Landing page**: crabagent builds a landing page about itself, promoting Sandcrab as open-source production agent sandboxing. It uses the shared `three-kit` 3D scenes (mounted read-only), which the presentation reuses.
- **Deliverables**: `docs/site/` holds the bench report, the walkthrough, the 3D presentation, and the crab symbology. All are local static HTML.

## Risks & open questions

- **No KVM on this VPS**: the VPS handles Docker dev; Firecracker and the benchmarks run on kvm-homelab (pending the spike).
- **2 vCPU** → parallel Ada builds contend for CPU. Cap at 3 concurrent agents with a shared `CARGO_TARGET_DIR` per worktree.
- **Python 3.15 / Node 26 availability** in `uv` / official images. If a pinned version is missing, fall back to the latest stable and record it in the template.
- **Egress allowlist is not enforced** in DockerDev (the proxy comes in Phase 3). Unrestricted networking is required for `npm install` in the harness.
- **VPS hardening applied**: ufw (SSH only), fail2ban, root login key-only, Docker publishes to 127.0.0.1 only.
  `nicolas` password login is still enabled; disabling it is recommended once you've confirmed your own key login. The `docker` group is root-equivalent (accepted for a dev box).
