An architect of the impermanent, born of iron and grit, carving safe harbors from the chaotic shoreline.

Sandboxes for AI agents. Press → to begin.

02 · The problem

Agents need real computers

Agents install packages, edit files and run code. Put them all on one shared box and one bad command breaks everyone’s work.

03 · Molting

One sandbox per turn

Spawn, wait for crabd’s hello, call tools, destroy. On Docker: spawn → ready p50 227–258 ms, destroy p50 96–104 ms.

04 · One wire

One protocol, every backend

SDK, CLI and crabagent send the same frames: a 4-byte length, then JSON-RPC. Unix socket into Docker, vsock into Firecracker.

05 · Toolbelt & tide clock

Tools inside crabd

Sixteen native Rust tools. A bash timeout kills the whole process group. Output keeps head and tail, 32 KiB per stream.

06 · Burrow · window & door

Workspaces outlive sandboxes

The burrow stays while shells molt. Mounts are read-only windows or read-write doors. Hosts edit between turns; Firecracker syncs an ext4 drive back.

07 · Tide pool vs. sealed jar

What isolates what

Docker: a hardened container on the shared host kernel, for single-tenant, trusted hosts. Firecracker: its own kernel behind KVM, built, first real-KVM benchmarks in the report.

08 · Refuse, never downgrade

Unsafe requests fail loudly

No silent backend fallback. Symlink and rename-swap tricks hit fd-relative openat2; overlapping workspace roots are refused. Three review rounds ended in PASS.

09 · The numbers

Measured, and what isn’t yet

Canonical Docker run on dev-vps (2-vCPU SSD VPS): n=30 per cell, p50 bars, p95 whiskers. Firecracker and libkrun were measured on other hosts (bare-metal KVM, Apple M2), so they stay dashed here; the full report compares them host by host.
