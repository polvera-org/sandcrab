04 · LATENCY

Per-cell latency

Where spawn and teardown time goes

Docker backend timing marks (phases), each measured from the start of the operation. Bars show the median of each cumulative mark across n=30, so segment widths are differences of medians, not medians of differences.

Workspace cost: spawn_ready and ws_attach, separate and combined

On Docker the bind mount happens inside spawn_ready, so the spec's spawn_ready_with_ws is the p50 difference against W0. ws_attach is the post-ready list_dir verification. The combined chart adds the two per iteration.

All latency metrics

Template × workspace mode. W0 = no workspace; W1 = about 300 files / 2 MB, read-write at /workspace; W2 = 5,000 files / 50 MB, read-only at /data. The 95% CI is a bootstrap of the p50. p99* is indicative (n < 100). Steady-state call.* metrics are 30 calls × 30 sandboxes after 5 warm calls each.

08 · DECISION

Recommended default backend: deferred

The spec's decision framework (§7) has two gates and then a weighted score per deployment context. The gates can be applied today. The scoring cannot: every criterion except platform availability is a ratio against the best measured backend, and only one backend was measured.
